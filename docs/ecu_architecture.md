# ECU 架构文档

## 1. 系统架构总览

## 2. 实时性设计

### 线程优先级层次

| 优先级 | 线程 | 功能 |
|--------|------|------|
| 最高 | 硬件中断(EXTI) | 触发信号边沿捕获 |
| 高 | ADC转换完成中断 | 高速ADC数据读取 |
| 中高 | 定时器中断 | 角度事件触发(喷油/点火) |
| 中 | 主循环(1000Hz) | 控制计算核心 |
| 中低 | 通信线程 | CAN/TunerStudio/串口 |
| 低 | 空闲循环 | 后台维护任务 |

### 关键实时保证

1. **触发信号处理是中断级的**: 曲轴传感器每个齿的信号产生硬件中断，中断服务函数必须尽快完成解码，然后将调度任务交给定时器。
2. **角度事件调度**: 燃油喷射和点火需要在精确的曲轴角度执行。调度器将角度转换为时间，使用硬件定时器产生精确延迟。
3. **CPU时间分片**: 主循环中的不同频率任务确保高优先级计算（如电子节气门在500Hz）比低优先级任务（如慢速传感器在20Hz）获得更多CPU时间。

## 3. 配置系统

### 配置数据流

```
firmware/fome_config.txt (配置定义)
        ↓
java_tools/configuration_definition (代码生成)
        ↓
firmware/generated/ (C/C++头文件)
        ↓
TunerStudio .ini (通信接口)
```

**关键设计原则**: 所有配置参数的"真实来源"是 `fome_config.txt`。C代码、TunerStudio通信协议和内存布局都从这个单一来源生成，确保各子系统对配置格式的理解完全一致。

### 配置存储

配置保存在STM32的内部Flash中。启动流程：
- `loadConfiguration()` 从Flash加载配置
- `rememberCurrentConfiguration()` 验证并应用配置
- 如果配置损坏或版本不匹配，使用默认值

### LiveData 系统

`firmware/integration/LiveData.yaml` 定义了从ECU实时发送到TunerStudio的数据对象。包括传感器值、执行器状态、中间计算结果等。与配置系统使用相同的代码生成工具，保证通信协议的一致性。

## 4. 模块化系统 (`EngineModule`)

发动机模块系统使用C++模板元编程实现类型列表：

```c
using engine_modules_t = decltype(
    make_tuple(
        InjectorModel(),
        IdleController(),
        AlternatorController(),
        AcController(),
        BoostController(),
        // ... 更多模块
    )
);
```

每个 `EngineModule` 实现多个回调接口：
- `onFastCallback()` - 250Hz快速回调
- `onSlowCallback()` - 20Hz慢速回调
- `onEnginePhase()` - 每个触发事件回调
- `onEngineStop()` - 发动机停止时回调
- `onConfigurationChange()` - 配置变更时回调

**为什么使用类型列表而非虚函数**: 嵌入式环境禁用了RTTI和虚函数(`-fno-rtti`)。使用编译期类型列表和模板可以避免运行时多态，同时保持接口的灵活性。编译器可以在编译期展开所有模块的调用链，实现零开销抽象。

## 5. 错误处理策略

### 断言恢复机制

```c
if (setjmp(jmpEnv) == 0) {
    // 正常初始化路径
} else {
    // 断言失败恢复路径
    // 尝试继续运行，尽管部分功能可能不可用
}
```

### 限速管理 (`limp_manager.cpp`)

限速管理器跟踪多个发动机保护条件：
- 爆震检测到 → 推迟点火
- 进气温度过高 → 减少增压 / 加浓混合气
- 油压过低 → 限制转速
- 传感器故障 → 回退到默认值

### 错误检测

- 触发错误检测: 连续错误超过阈值(4次/6个同步点)判定为触发故障
- 同步超时: 如果超过一定时间没有触发信号，判定为发动机停止
- ADC无效检测: 开路/短路检测（电压超出范围）

## 6. 通信协议

### TunerStudio 协议

ECU通过串口或USB运行TunerStudio协议：
- 实时数据显示 (LiveData)
- 配置读/写
- 指令执行 (自校准、重置等)

### CAN 总线

支持多种CAN协议：
- 宽域氧传感器(CAN wideband)
- 直出CAN仪表盘
- CAN-based 扩展IO

### Lua脚本引擎

用户可以编写Lua脚本自定义ECU行为：
- 读取传感器值
- 控制GPIO输出
- 实现自定义逻辑
- 运行时加载，无需重新编译固件
